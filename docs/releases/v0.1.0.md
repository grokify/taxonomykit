# Release Notes v0.1.0

**Release Date:** October 14, 2026

## Overview

This is the initial release of TaxonomyKit, a Go toolkit for hierarchical
taxonomies — category trees, topic trees, product hierarchies, subject
classifications. It owns the *structure* (nodes, parent relations, ordering,
per-language labels and slugs) and the operations applications need on it;
the *content* stays in your own CSV, PSV or JSON file.

The release covers the whole of Phase 1 of the [roadmap](../specs/ROADMAP.md):
the core tree, the flat and JSON codecs with a generated schema, and the CLI.
SKOS interchange and document operations (subtree, merge, diff) follow in
v0.2.

## Installation

```bash
go get github.com/grokify/taxonomykit@v0.1.0
go install github.com/grokify/taxonomykit/cmd/taxonomykit@v0.1.0
```

The library has no dependencies outside the Go standard library and builds
with `CGO_ENABLED=0` on every platform Go supports. The CLI depends on Cobra.

## Features

### A validated tree with polyhierarchy

`Build` turns a flat `[]Node` into an immutable, indexed `Tree`, or returns
the first problem it finds; `Validate` returns every problem at once with a
stable code (`cycle`, `parent.missing`, `slug.duplicate`, …) so a tool can
list them. A node may have several parents; the first is the *primary*
parent, which is what `Lineage`, `Breadcrumb` and `Depth` follow, while
`Lineages` enumerates every root path. Sibling order is defined — explicit
`Order` first, then default-language name, then id — so menus and sitemaps
never change between builds.

### Localization that says what it did

Labels are keyed by lowercase BCP-47 tag. A lookup in `pt-br` falls back to
`pt`, then to the document's default language, and every `Crumb` records the
language it was actually taken from, so a site can decide whether to mark a
fallback. `BySlug` resolves a URL segment per language, with explicit slugs
taking precedence over fallback slugs.

### Files in, files out

The `flat` package reads CSV, TSV and PSV with a header row or a column
mapping. One row per node and language; a node listed twice under different
parents becomes a multi-parent node instead of silently keeping the last
parent, which is how legacy single-parent files migrate without losing
links. The JSON `Document` format round-trips byte for byte and ships with
a JSON Schema generated from the Go types.

### Command line

```bash
taxonomykit validate topics.psv              # every problem, exit 1 if any
taxonomykit convert topics.psv --to json     # csv | tsv | psv | json
taxonomykit tree topics.json --lang es       # indented listing with slugs
taxonomykit lineage topics.psv mortgage --all
```

## Known Limitations

- One scheme per document; multiple independent trees (facets) are a v0.2
  question.
- No SKOS import or export yet; the model is designed to map onto SKOS and
  the JSON-LD codec is the first item of Phase 2.
- `Lineage` and `Depth` consider only primary parents. Use `Lineages` for
  every path.
- Returned `*Node` values belong to the tree and must not be modified.
